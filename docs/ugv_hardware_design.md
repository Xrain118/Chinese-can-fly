# High-Level UGV Hardware Design

## System Architecture

This design targets the advanced disaster-search-and-delivery track with a
four-wheel differential unmanned ground vehicle.

- STM32F407VET6 is the real-time motion controller.
- Raspberry Pi is the onboard computer for ROS2, Wi-Fi hotspot, lidar, mapping,
  localization, path planning, and air-ground target exchange.
- Two TB6612FNG modules drive the four wheel motors. One TB6612 is assigned to
  the left side, and one TB6612 is assigned to the right side.
- ICM42688 is connected directly to STM32F407 through SPI.
- Gray-scale tracking sensors and ESP32 are not used.

## STM32F407 Pin Allocation

### Dual TB6612FNG Motor Drive

PWM is generated by TIM5 at 20 kHz.

| Function | STM32 Pin | Timer Channel | TB6612 Signal |
| --- | --- | --- | --- |
| Left-front PWM | PA0 | TIM5_CH1 | Left TB6612 PWMA |
| Left-rear PWM | PA1 | TIM5_CH2 | Left TB6612 PWMB |
| Right-front PWM | PA2 | TIM5_CH3 | Right TB6612 PWMA |
| Right-rear PWM | PA3 | TIM5_CH4 | Right TB6612 PWMB |
| Left-front IN1 | PE0 | GPIO | Left TB6612 AIN1 |
| Left-front IN2 | PE1 | GPIO | Left TB6612 AIN2 |
| Left-rear IN1 | PE2 | GPIO | Left TB6612 BIN1 |
| Left-rear IN2 | PE3 | GPIO | Left TB6612 BIN2 |
| Left driver standby | PE4 | GPIO | Left TB6612 STBY |
| Right-front IN1 | PE5 | GPIO | Right TB6612 AIN1 |
| Right-front IN2 | PE6 | GPIO | Right TB6612 AIN2 |
| Right-rear IN1 | PE7 | GPIO | Right TB6612 BIN1 |
| Right-rear IN2 | PE8 | GPIO | Right TB6612 BIN2 |
| Right driver standby | PE10 | GPIO | Right TB6612 STBY |

PE9 and PE11 remain reserved for the left-front encoder. PE12 is the software
e-stop input. PE13 through PE15 remain free for payload release or expansion.

### Safety and battery monitoring

| Function | STM32 Pin | Electrical connection |
| --- | --- | --- |
| Software e-stop | PE12 | Active-low input; button pulls the pin to GND |
| Battery voltage | PC0 / ADC1_IN10 | Midpoint of a 100 kOhm / 33 kOhm divider |

The software e-stop supplements, but does not replace, a physical emergency
stop that removes both TB6612 STBY signals or motor power. Fit a capacitor near
PC0 if motor switching noise makes the ADC reading unstable.

Firmware defaults to a 3S battery, a 9.6 V stop threshold, and a 10.2 V recovery
threshold. For a 2S battery, change `POWER_BATTERY_CELL_COUNT` in
`Hardware/PowerMonitor.h` before building.

### Encoders

| Wheel | STM32 Pins | Timer |
| --- | --- | --- |
| Left-front | PE9 / PE11 | TIM1 |
| Left-rear | PD12 / PD13 | TIM4 |
| Right-front | PB4 / PB5 | TIM3 |
| Right-rear | PC6 / PC7 | TIM8 |

Four independent encoders are preferred. If the mechanical build only has two
encoders, install them on one wheel per side and leave the unused inputs open or
adapt firmware later.

### IMU

| Function | STM32 Pin |
| --- | --- |
| ICM42688 SCK | PB13 |
| ICM42688 MISO | PB14 |
| ICM42688 MOSI | PB15 |
| ICM42688 CS | PD8 |
| ICM42688 INT | PD9 |

### Raspberry Pi Link

| Function | STM32 Pin | Raspberry Pi Side |
| --- | --- | --- |
| STM32 TX | PD5 / USART2_TX | Pi UART RX |
| STM32 RX | PD6 / USART2_RX | Pi UART TX |
| GND | GND | GND |

Default UART speed is 115200 bps. The Pi should send wheel commands only after
the STM32 has been started with the `START` command. The direct command format is:

```text
PWM <left_pwm> <right_pwm>
```

Both values are signed and limited to -1000..1000. Positive values drive the
vehicle forward after motor polarity has been calibrated.

While the chassis is running, the Pi must send `PWM`, `SPEED`, `HEARTBEAT`, or
`PING` at least once every 300 ms. A timeout stops the motors and latches a
fault. Use `FAULT CLEAR` after the active cause has been removed, then issue
`START` again.

Telemetry includes `F` (fault bit mask), `BV` (battery millivolts), `ES`
(e-stop), `IMU` (IMU health), and `WD` (command watchdog age in milliseconds).
An `I` frame carries raw accelerometer, gyroscope, and temperature samples at
20 Hz. The Raspberry Pi bridge publishes these as `/imu/data_raw`.

| Fault bit | Value | Meaning |
| --- | --- | --- |
| 0 | 1 | Raspberry Pi command timeout |
| 1 | 2 | Emergency stop active |
| 2 | 4 | Battery below threshold |
| 3 | 8 | IMU missing or stale |
| 4 | 16 | Encoder missing or wheel stalled while closed-loop is enabled |
| 5 | 32 | Battery ADC conversion failure |

## Power Plan

- Main battery: choose 2S or 3S lithium according to the motor voltage.
- Motor VM: route through a power switch, fuse, bulk capacitor, and TVS diode.
- TB6612 logic VCC: use 3.3 V to match STM32 IO directly.
- STM32 and ICM42688: stable 3.3 V rail with local decoupling.
- Raspberry Pi: independent 5 V regulator rated at 3 A minimum; use more margin
  if the lidar is powered from the Pi USB port.
- All grounds must be common, but high-current motor return should not pass
  through the STM32 ground path.

## Raspberry Pi Role

- Runs ROS2.
- Opens the Wi-Fi hotspot used by the UAV onboard computer.
- Receives target class, target position, confidence, mission id, and heartbeat
  over ROS2 DDS.
- Reads the 2D lidar through USB.
- Runs localization, mapping, obstacle avoidance, and path planning.
- Converts planned motion into signed left/right PWM or a later velocity command
  and sends it to STM32 over UART.

## Bring-Up Checklist

1. Verify STM32 clock, SWD download, and USART2 logs.
2. Verify ICM42688 `WHO_AM_I` over SPI.
3. Test each TB6612 channel independently with low PWM.
4. Calibrate motor direction signs in `Motor.h`.
5. Verify all encoder directions in `Encoder.h`.
6. Test `START`, `PWM 200 200`, `PWM 200 -200`, and `STOP` over UART.
7. Stop sending heartbeats and confirm the chassis stops within 300 ms.
8. Test the PE12 e-stop and verify the independent hardware e-stop path.
9. Compare `BV` against a calibrated multimeter and adjust the divider constants.
10. Enable encoder closed-loop mode after open-loop motor direction is correct.
11. Start the Raspberry Pi hotspot and confirm the UAV computer can join it.
12. Confirm ROS2 DDS target messages between the UAV computer and the Pi.
13. Confirm lidar scan, localization, path planning, UART motion output, and
    STM32 fail-safe stop behavior.
